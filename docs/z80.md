# Z80 core and vector evidence

The Z80 is instance-owned C17 state in `gw_machine`. Its documented clock ratio is one Z80 T-state per 15 Genewhip master ticks. Each call to `gw_z80_cycle` performs at most one machine-cycle or internal-delay step; M1 fetch, memory, I/O, refresh and internal steps have distinct cycle kinds. Multi-step instructions retain micro-operation state so callers can stop and resume between steps. `gw_z80_at_boundary` reports whether an instruction has retired; retirement is the safe stop boundary (D-39/D-41). Every documented unprefixed opcode byte is decoded in this slice, including register and memory loads, stack/exchange, ALU/rotate, control flow, interrupt control, HALT, and immediate I/O. HALT repeats M1 at the held PC. DI/EI state includes the one-instruction EI delay. The scheduler synchronizes Z80 work before 68000 bus commits and run boundaries.

Cold initialization holds reset asserted, leaves BUSREQ clear, initializes PC/IFF/IM/I/R to zero and the remaining 8-bit register pairs, index registers, SP and WZ to `0xffff` as a documented model choice. Console reset clears the CPU's in-flight state and retains its 8 KiB RAM as a model choice. The 68000-facing Z80 window, BUSREQ and RESET model is implemented in `src/z80_bus.c`; these tests establish conformance to the selected model, not physical-board timing.

## Interrupt behavior (Plan GW-03-16)

Zilog UM0080 pp. 18–19 defines reset clearing IFF1/IFF2, EI deferring INT through the following instruction, HALT continuing M1 until an accepted interrupt, and NMI copying IFF1 to IFF2 before clearing IFF1. NMI vectors to `$0066`; RETN restores IFF1 from IFF2. The implementation models NMI's documented 11 T entry and RETN, and the hooks contract exercises all three maskable modes: IM0 with an injected RST acknowledge byte, IM1 to `$0038`, and IM2 through `(I << 8) | acknowledge_byte` with 19 T entry.

The console VBlank line is modeled as a 32-T pulse beginning at the first Z80 cycle at or after line 224. This width is an explicit assumption: it exceeds the longest documented instruction form currently implemented (23 T) plus phase slack and ends before the tested handler's EI/RETI can re-enable acceptance. It is not a measured Genesis pulse width. The guest fixture verifies ten VBlank services, including EI delay and HALT release. Its fixed 68000 upload/reset launch and source-counted Z80 delay place EI retirement at tick 766215 inside the first assumed INT pulse [766080, 766560). The following HALT retires at 766275; the first IM1 entry saves return PC `$00B1` to guest RAM. Removing EI deferral instead saves `$00B0` and fails the named `pending-int-ei-defers-through-halt` oracle. The nested Z80 source/include stage is rebuilt and compared by the fixture pipeline.

Genesis INT acknowledge data is unresolved. The live VBlank seam therefore services IM1 only; it does not invent an IM0 opcode or IM2 vector byte. IM0/IM2 CPU semantics are tested by private hooks that supply the acknowledge byte. Hardware acknowledge behavior remains unknown and is excluded from claims of board compatibility.

The extended ASan/UBSan lane runs `gw_bounded_fuzz z80-stream` and `audio-calls`. The Z80 mode uploads seeded 256-byte programs through the 68000 RESET/BUSREQ window, runs four fields on two machines, and compares public tick, documented stop reason, work RAM and PCM hashes. The audio mode varies valid/invalid rates, trace capacities, read capacities (including zero and `UINT32_MAX`), and run targets; it checks documented statuses, unchanged outputs on rejected reads, and frame indices including reported queue loss. Each emits denominator/pass/fail/unknown/skipped counts. These bounded checks establish reproducibility and memory safety for the exercised inputs, not general compatibility or coverage completeness.

## Arbitration

The 68000 accesses the Z80 RAM window at `$A00000-$A03FFF` only while BUSREQ is granted. The 8 KiB RAM mirrors across that window. Only byte accesses are modeled there. A write made without grant is ignored; a read without grant returns a Genewhip model value, but its hardware value is unknown and is reported without an expectation by `bus_arb_seam`.

BUSREQ is written as a word at `$A11100` (`0xA11100`): `$0100` requests the bus and `$0000` releases it. The selected read status is word D8, mask `$0100`, equivalently bit 0 of the even-address byte at `$A11100`, mask `$01`. A pending request reads set; granted access reads clear. This follows the explicit read table and polling procedure in Sega's *Technical Overview* 1.00, §4, printed p.76 ([mirror 1](https://www.backoldgaming.com/data/medias/files/documents/Genesis_Technical_Overview.pdf), [mirror 2](https://segaretro.org/images/1/18/GenesisTechnicalOverview.pdf)). The two mirrors are copies of one source, not independent corroboration. Sega's *Genesis Sound Software Manual* (1992-02-21), printed p.2 ([PDF](https://gendev.spritesmind.net/files/md/tech/Genesis%20Sound%20Software%20Manual%20%5B1992-02-21%5D.pdf)), gives the opposite polarity in its bit-0 status box. The source class is **documented in Technical Overview; conflicting primary statement unresolved**. No erratum, precedence proof, or physical-board measurement resolves that conflict. D-44.2 is therefore model-conformance evidence, not independent hardware truth. The word D0 is not the status bit.

The model samples a pending BUSREQ at a Z80 machine-cycle boundary strictly after the request's bus-commit tick (D-41). Cycle edges use the absolute 15-master-tick Z80 clock; releasing BUSREQ resumes on the next strict global clock edge after the release commit, never by replaying an earlier cycle start. When BUSREQ and RESET become eligible at the same modeled boundary, BUSREQ grant sampling is processed first and holds the Z80 before another cycle is issued. This is the implementation's deterministic tie-break rule.

RESET is written as a word at `$A11200`: `$0000` asserts reset at the write commit; `$0100` releases reset on the next strict Z80 clock edge. Reset clears PC and IFF state (including IFF2) and sets I to zero while preserving Z80 RAM. The original guest observes its restart marker and stores `LD A,I` results for the I and IFF2 checks in `bus_arb_seam` case `d44_5_reset_pc0_i_iff2`.

Status bits other than word D8/even-byte bit 0, the `$A11100` value before BUSREQ is requested, its value while Z80 reset is asserted, and the data returned by ungranted Z80 RAM reads are unknown. The current model returns word `$0100` for the two unrequested/reset status reads and `$FF` for an ungranted RAM read; `bus_arb_seam` reports all three observations as `unknown` without asserting those values. A Z80-window byte access consumes 4 × `GW_CPU_DIVIDER` = 28 master ticks in this model (Genewhip-defined timing; not a hardware-qualified wait-state measurement).

Z80 reset at `$A11200` asserts the YM2612 reset wrapper on the asserted edge. The basis is the Sega *Genesis Sound Software Manual* (1992-02-21), printed p. 2 / PDF p. 6, which states that Z80 reset also clears the FM sound source; see `docs/audio.md` “Reset search record (D-42; approved bounded exception, exact net unknown)” and the user-approved `03-FM-RESET-AMENDMENT.md`. The exact VA3 reset net, pulse width and complete silicon state effects remain unknown. The pinned ymfm reset-field inventory, ignored writes while held, repeated-edge handling, silence step, retained sample/PCM continuity, and DAC resume are provisional implementation contracts, not hardware-confirmed behavior. This reset choice is separate from BUSREQ.

Named automated evidence: `z80_arbitration_contract` checks the D-44.1 request/grant ordering and tick order; `d44_2_poll_sequence` checks the guest's set-to-clear poll observations under the documented/conflicted source class; `d44_4_ungranted_write_ignored` checks the sentinel after an ungranted write; and `d44_5_reset_pc0_i_iff2` checks guest-visible restart state. The admitted fixture is `genewhip-seam-bus-arb-v1`, tested by `bus_arb_seam`; its negative control is `bus_arb_seam_negative_control`. `z80_sync_idempotence_bus_arb` applies the Plan 03-13 synchronization-partition test to this ROM. These results do not establish the unresolved primary-source polarity conflict as a physical fact.

The seam seeds `$A5` while granted and attempts `$5A` without grant. Its Z80 program never writes that sentinel, so a wrongly accepted write cannot be repaired before observation. The source calculates the first status read at tick 10080 before grant at 10095 using the startup instructions and individual JR machine-cycle/internal-delay boundaries. The negative control rejects both a changed sentinel expectation and a reversed poll observation at their named assertions; three hardware-unknown cases remain unknown in its eight-case denominator.

## Z80 memory and device map (Plan 03-15)

This implementation has a deliberately small fail-closed map. The guest's original Z80 driver in `tests/devices/roms/z80_bank.s` and its enclosing 68000 harness exercise the supported banked-ROM and PSG paths; `z80_bank_seam` checks the source-authored marker, source-tagged PSG writes, and the tone derived from the documented clock formula.

| Z80 address | Modeled behavior | Evidence and limits |
|---|---|---|
| `$0000-$3fff` | 8 KiB work RAM mirrored through the window | 8-bit reads and writes; mirrored by the low 13 address bits. |
| `$6000-$60ff` | Bank serial register | A write shifts in bit 0, least-significant bit first, retaining nine bits. The model applies one Z80 T-state worth of 15 master ticks after the write. This is a Genewhip synchronization choice, not a measured or documented cartridge wait total. |
| `$8000-$ffff` | 9-bit bank window | Read-only access through `gw_bus_peek` at `bank * 0x8000 + (address - 0x8000)`; out-of-ROM reads fail closed as unsupported-address stops. Writes are unsupported. |
| I/O `$7f11` | PSG data port | Writes enter the shared PSG and retain `GW_AUDIO_SOURCE_Z80` with the Z80 cycle tick. Other I/O ports, including YM2612 and VDP-facing addresses, fail closed. |

The nine-bit register permits addresses through 4 MiB; actual ROM size remains authoritative, so an address below 4 MiB can still be rejected when the loaded image is smaller. Mapping the bank window onto 68000 work RAM or devices remains unresolved (research assumption A3); this implementation rejects every address outside the loaded ROM bytes. `z80_bank` derives its expected 16-byte marker from the assembler source and places it at ROM offset `$8000`, selected by serial bank value one. Its nested delay uses 60 × 60 loop iterations: 4 T-states for `DEC C`, 12 for each taken `JR NZ`, and a 15-master-tick Z80 divider. The delay supplies over 850,000 model master ticks between tone setup and the next PSG write, enough for repeated periods at the derived 873.9 Hz; this arithmetic describes whole instruction timing and does not assert external wait-state timing. The source's four 4,000-iteration 68000 setup loops keep BUSREQ released long enough for the Z80 to complete that interval while keeping the entire fixture within the four-field split-equivalence run.

`bus_arb_midinstr` exercises the public memory seam when BUSREQ is requested during a Z80 `PUSH`: the 68000 observes only the first pushed byte until grant, then observes the completed stack value after release. The direct contract additionally pauses `PUSH` and `LDIR` between micro-operations and verifies exact-once resumption. These tests validate the selected scheduling contract, not physical mid-instruction arbitration timing.

## Stop and fault encoding

These are the `fault-a` forms approved and recorded at the Plan 03-01 checkpoint:

The exact fault address forms are `0x40000000 | z80_pc` and `0x40000000 | z80_address`.

| Stop reason | Encoding | Meaning |
|---|---|---|
| `GW_STOP_UNSUPPORTED_INSTRUCTION` | `fault_address = 0x40000000 \| z80_pc`; `opcode = (prefix << 8) \| opcode_byte` | PC of the opcode's first byte, including a prefix. |
| `GW_STOP_UNSUPPORTED_ADDRESS` | `fault_address = 0x40000000 \| z80_address` | 16-bit memory or I/O address driven by the unsupported cycle; `opcode` remains the faulting opcode word. |

Bit 30 marks a Z80 fault. The 68000 address is 24-bit, and bit 31 remains reserved for the VDP-mode encoding. Unsupported Z80 addresses stop with the address form above.

## Pinned corpus and admission

The evidence source is [`SingleStepTests/z80`](https://github.com/SingleStepTests/z80) at commit [`ebe1875d48f374bcfd4b505d8eb8ee751568b5f7`](https://github.com/SingleStepTests/z80/tree/ebe1875d48f374bcfd4b505d8eb8ee751568b5f7), licensed MIT. `tests/z80/manifest.json` records that exact revision, the reviewed license, generator options, every `v1/` tree path with its Git blob SHA-1 and byte size, and SHA-256 plus Git blob identity for every corpus file used by this slice. The runner fails closed on data, selection, license, size, or digest mismatch.

The committed PR slice is `tests/z80/selected.json` (1,433 records, 1,194,443 bytes) from 692 pinned opcode files. It selects indices 0 and 999 where present and includes the first pinned taken and untaken sample for every conditional branch encoding where both occur in the source. DD/FD register-copy aliases and DDCB/FDCB SLL are excluded as gated undocumented forms. The selection rule and pinned corpus denominator are stored in the manifest. Run `python3 tests/z80/run_z80_vectors.py --select --fetch --corpus-dir build/z80-vector-corpus` to reproduce it. The scheduled invocation in `scripts/ci/extended-gate.sh` traverses the full pinned inventory one source file at a time, checking each Git blob SHA-1 and byte size before use. The hooks-only adapter checks registers, listed memory bytes, input/output port values, ordered M1/refresh/memory/I/O transactions, and total T-states. Negative controls mutate register state, the documented unaffected C flag on block I/O, and an ordered transaction; each must be detected.

All 1,433 selected records match on the fields and transactions the adapter compares; there are zero mismatches and zero unsupported records. There are **zero unconditional whole-record passes**: every row remains a partial-field match. Selected-record field gates overlap: X/Y flags changed in 466 records, WZ/MEMPTR in 468, Q is unresolved in 1,027, and Zilog-unspecified block-I/O S/H/PV flags apply to 16 records. Zilog's [Z80 CPU User Manual UM008011-0816](https://www.zilog.com/docs/z80/um0080.pdf) explicitly marks S, H, and P/V unknown for INI/INIR/IND/INDR (printed pp. 298, 300, 302, 304) and OUTI/OTIR/OUTD/OTDR (pp. 309, 311, 313, 315); it defines Z from post-decrement B, N set, and C unaffected. The original pre-gate discrepancies are preserved in Plan 03-11's summary with their exact 11 record IDs. Conditional encodings have 72 selected taken cases and 75 selected untaken cases.

The scheduled full lane checked all 1,604 pinned files (1,374,635,394 bytes; 1,604,000 records) against the manifest's Git blob SHA-1 and byte-size inventory. Of these, 692,000 records were in the explicit documented comparison roster: 692,000 partial-field matches, zero mismatches, zero unsupported outcomes, and zero unconditional whole-record passes. The remaining 912,000 are reported as named gates rather than passes: 30,000 `undocumented-opcode`, 432,000 `unlisted-index-prefix`, and 450,000 `unlisted-indexed-CB-encoding`. Field gates overlap the compared records: X/Y 232,347; MEMPTR 220,925; Q 496,865; UM0080-unspecified block-I/O flags 8,000. The index gates retain encodings outside the manual's documented IX/IY substitutions and the DDCB/FDCB memory forms; the report does not assert behavior for those encodings. The complete counts and scheduled command are in `tests/z80/manifest.json`; per-run results go to `build/extended/reports/z80-vectors.json`.

This is **functional and bus-state agreement, not hardware, Genesis timing, or game-compatibility evidence**. The selected records were generated by an Ares-derived process as described by the upstream project; the exact generator executable revision is not stated by the corpus. The refresh bus value during waits is intentionally not treated as a memory transaction. The vector corpus is data only; no third-party CPU implementation is included.
